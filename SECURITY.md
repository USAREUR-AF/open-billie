# Security policy

## Supported versions

Security fixes are made against the latest code on the default branch. No older release line is currently maintained.

## Reporting a vulnerability

Do not report suspected vulnerabilities in public issues, pull requests, or discussions. Use GitHub's private vulnerability reporting for this repository if it is enabled. Otherwise, contact the repository maintainer privately through the contact information on the repository's GitHub profile and include only the information needed to reproduce and assess the issue.

Do not include credentials, private keys, real sensor captures, personal data, or operational network details in a report unless the maintainer requests a secure transfer method. The repository does not promise a particular response time; the maintainer will acknowledge reports and coordinate a fix and disclosure with the reporter.

## Scope

Reports may cover the Open Billie platform, its provisioning and kid-management tools, and the synthetic OETF example. Third-party dependencies should be reported to their upstream maintainers as well when the issue is in upstream code.
